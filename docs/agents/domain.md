# Domain documentation

This is a single-context application. Before domain exploration, read root `GLOSSARY.md` if present and ADRs relevant to the affected area under `docs/adr/`. If absent, proceed silently.

Use glossary terms in code, tests, issues and proposals. Apply `domain-modeling` when terms need clarification or domain decisions need work. Create the glossary only when the first real term is resolved; keep it free of implementation details. Create ADRs lazily for meaningful trade-offs that are hard to reverse and surprising without context. Surface conflicts with an existing ADR explicitly before proposing a change.

No glossary, ADR or invented domain vocabulary is needed for workflow setup. `grill-with-docs` combines clarification and documentation only when explicitly requested.
